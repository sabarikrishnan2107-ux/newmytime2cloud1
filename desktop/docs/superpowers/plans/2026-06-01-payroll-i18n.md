# Payroll Pages Internationalization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the admin payroll module, employee-edit payroll, and payroll settings tabs change language with the existing EN/AR/FR/HI switcher.

**Architecture:** Add one top-level `"payroll"` namespace to each existing `locales/<lang>/common.json`, then wire `useTranslation()` + `t()` into every in-scope component — identical to how dashboard/employees already translate. No i18n infrastructure changes. Arabic stays LTR (existing design).

**Tech Stack:** Next.js (App Router), React, `react-i18next` / `i18next` (already installed), Tailwind.

---

## IMPORTANT execution notes

- **No test framework exists** in `frontend-new` (only `dev`/`build`/`start`). TDD-by-unit-test does not apply. The automated guard for this work is a **locale key-parity script** (Task 0) plus `npm run build`. Functional correctness is confirmed by **manually toggling the language** on each page.
- **Claude must NOT run `git commit`/`git push`.** Each "Commit" step is performed by the USER. The executor should pause at each commit checkpoint and tell the user what to commit.
- **Translate at the right layer.** Leaf components that only render a prop (e.g. `KPICard` renders `title`) are NOT translated internally — their PARENT passes `t('...')`. Components that map a value to a label internally (e.g. `StatusBadge` maps a status string) translate internally.
- **Never translate dynamic API data** (names, amounts, dates, currency) — only static UI chrome and known enum→label maps.
- **Key convention:** `payroll.<section>.<element>`. Shared words live ONLY in `payroll.common.*` and are reused.

## Task 0: Locale key-parity guard script

**Files:**
- Create: `frontend-new/scripts/check-locale-parity.mjs`

- [ ] **Step 1: Create the parity script**

```js
// frontend-new/scripts/check-locale-parity.mjs
// Verifies every key in en/common.json exists in ar, fr, hi (and vice-versa).
// Run: node scripts/check-locale-parity.mjs
import { readFileSync } from "node:fs";
import { fileURLToPath } from "node:url";
import { dirname, join } from "node:path";

const __dirname = dirname(fileURLToPath(import.meta.url));
const LANGS = ["en", "ar", "fr", "hi"];

function flatten(obj, prefix = "", out = {}) {
  for (const [k, v] of Object.entries(obj)) {
    const key = prefix ? `${prefix}.${k}` : k;
    if (v && typeof v === "object" && !Array.isArray(v)) flatten(v, key, out);
    else out[key] = true;
  }
  return out;
}

const data = {};
for (const lang of LANGS) {
  const path = join(__dirname, "..", "src", "locales", lang, "common.json");
  data[lang] = flatten(JSON.parse(readFileSync(path, "utf8")));
}

const base = Object.keys(data.en);
let failed = false;
for (const lang of LANGS.filter((l) => l !== "en")) {
  const missing = base.filter((k) => !data[lang][k]);
  const extra = Object.keys(data[lang]).filter((k) => !data.en[k]);
  if (missing.length) {
    failed = true;
    console.error(`\n[${lang}] MISSING ${missing.length} keys present in en:`);
    missing.forEach((k) => console.error(`  - ${k}`));
  }
  if (extra.length) {
    failed = true;
    console.error(`\n[${lang}] EXTRA ${extra.length} keys not in en:`);
    extra.forEach((k) => console.error(`  + ${k}`));
  }
}

if (failed) {
  console.error("\n❌ Locale parity check FAILED.");
  process.exit(1);
}
console.log(`✅ Locale parity OK — ${base.length} keys consistent across ${LANGS.join(", ")}.`);
```

Expected: `✅ Locale parity OK — <N> keys consistent across en, ar, fr, hi.`
(If it fails now, there is a pre-existing mismatch — note it but do not fix unrelated keys.)

- [ ] **Step 5: Wire `StatusBadge.jsx` to translate the status label internally**

The badge maps a backend status value to a styled label. Translate the displayed text via `payroll.common.statuses.<value>`, keeping the raw value for styling. Full replacement:

```jsx
"use client";

import { useTranslation } from "react-i18next";

const statusStyles = {
  draft: "bg-gray-100 dark:bg-gray-800 text-gray-600 dark:text-gray-400",
  pending: "bg-amber-100 dark:bg-amber-900/20 text-amber-700 dark:text-amber-400",
  approved: "bg-emerald-100 dark:bg-emerald-900/20 text-emerald-700 dark:text-emerald-400",
  paid: "bg-blue-100 dark:bg-blue-900/20 text-blue-700 dark:text-blue-400",
  rejected: "bg-red-100 dark:bg-red-900/20 text-red-700 dark:text-red-400",
};

export function StatusBadge({ status }) {
  const { t } = useTranslation();
  const key = status?.toLowerCase();
  const style = statusStyles[key] || statusStyles.draft;
  const label = t(`payroll.common.statuses.${key}`, { defaultValue: status });
  return (
    <span className={`inline-flex items-center gap-1 rounded-full px-2.5 py-0.5 text-[10px] font-bold uppercase tracking-wider ${style}`}>
      <span className="h-1.5 w-1.5 rounded-full bg-current"></span>
      {label}
    </span>
  );
}
```

(`defaultValue: status` means an unknown backend status falls back to its raw value instead of showing a key.)

## Per-component wiring pattern (apply in Tasks 2–7)

For EVERY component task below, follow these identical steps:

1. **Read the whole file** — scan JSX *and* non-JSX strings: headings, labels, table `<th>`, button text, tab names, `placeholder=`, empty states, `alert(...)`, `confirm(...)`, `toast(...)`, and any `const ... = "English"` label maps. List every user-facing English string.
2. **Skip dynamic data** — anything interpolated from API/props/state (names, amounts, dates) stays as-is.
3. **Add keys** under the task's `payroll.<section>` sub-tree to **all four** JSON files (EN verbatim from the source string; AR/FR/HI translated). Reuse `payroll.common.*` for shared words instead of new keys.
4. **Add the hook**: `import { useTranslation } from "react-i18next";` and `const { t } = useTranslation();` at the top of the component body.
5. **Replace** each listed string with `t('payroll.<section>.<key>')`. For interpolation use `t('key', { count })` with `"...{{count}}..."` in JSON.
6. **Verify**: `node scripts/check-locale-parity.mjs && npm run build`, then `npm run dev` and toggle all 4 languages on the affected page — confirm no English leakage (except intended dynamic data) and no layout shift.
7. **USER commits** with message `feat(payroll-i18n): translate <component>`.

Each task lists its `payroll.<section>` and the components it covers. Use the section name as the key prefix (e.g. Task 4 uses `payroll.register.*`).
